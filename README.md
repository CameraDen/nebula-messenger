# Nebula Messenger

Работающий full-stack MVP на основе HTML-прототипа. Сохранены исходный CSS, тёмная палитра, градиенты, боковая навигация, панели, карточки и сообщения. React заменяет локальную логику прототипа; аккаунты, сессии, диалоги и сообщения хранятся в постоянной серверной SQLite-БД через Prisma.

## Быстрый запуск (PowerShell)

Требуется Node.js **22.20+** и npm. Docker и PostgreSQL для этого режима не нужны.

```powershell
npm ci
Copy-Item .env.example .env
npm run db:generate
npm run db:migrate
npm run dev
```

Откройте **http://127.0.0.1:5173**. Используйте именно этот адрес, а не `localhost`: проверка Origin привязана к конфигурации. Регистрация доступна кнопкой «Создать аккаунт». Для проверки общения откройте вторую независимую браузерную сессию (другой браузер или инкогнито), создайте второй аккаунт. В первом аккаунте нажмите «Найти человека», введите имя или email второго и начните диалог. Демопользователи не создаются.

`Copy-Item` нужен только при первом запуске: не перезаписывайте настроенный `.env`. `db:migrate` применяет только ещё не выполненные миграции и не сбрасывает данные. Обёртка предварительно создаёт файл SQLite, что необходимо для schema-engine в текущем Windows-окружении.

## Доступ для устройств локальной сети

Остановите предыдущий сервер сочетанием Ctrl+C, затем выполните:

```powershell
npm run lan
```

Команда соберёт интерфейс, определит IPv4 Ethernet/Wi-Fi, запустит сервер на `0.0.0.0:3001` и автоматически установит `APP_ORIGIN` в сетевой адрес. Открывайте напечатанный адрес `http://<IP>:3001` и на серверном компьютере, и на остальных устройствах. Оставьте окно сервера открытым. В брандмауэре Windows должен быть разрешён входящий TCP 3001 для частной сети. Если порт занят, сначала остановите старый экземпляр.

При нескольких адаптерах адрес можно выбрать явно:

```powershell
$env:LAN_IP="192.168.1.100" # Замените на IPv4 своего компьютера
npm run lan
```

Режим LAN использует HTTP, без `NODE_ENV=production`. HTTPS-заголовки Upgrade-Insecure-Requests и HSTS включаются только при HTTPS в `APP_ORIGIN`; остальные заголовки Helmet сохраняются. Для UUID сообщений используется `crypto.getRandomValues`, доступный на HTTP-страницах локальной сети. `crypto.randomUUID` там может отсутствовать.

## Сборка и проверки

```powershell
npm run build
npm test
npx playwright install chromium
npm run test:e2e
```

- `build`: строгая проверка TypeScript и Vite-сборка в `dist/`.
- `test`: миграции в отдельной временной БД, интеграционные тесты настоящего HTTP/Socket.IO-сервера, удаление только созданного тестом файла. Рабочая БД не используется.
- `test:e2e`: отдельный сервер на порту 4173 и отдельная тестовая БД, два Chromium-контекста, десктоп 1440×900 и телефон 390×844. Адрес `http://nebula.test:4173` отображается тестовым браузером на loopback, но остаётся обычным HTTP-origin без secure context — это проверяет условия LAN. Проверяются регистрация, диалог, доставка в обе стороны, typing, история после перезагрузки, восстановление после офлайна, текстовый вывод HTML и мобильная навигация. Скриншоты — `artifacts/desktop.png` и `artifacts/mobile.png`. Для установленного Edge можно задать `$env:PLAYWRIGHT_CHANNEL="msedge"`.

При остановке Playwright средствами ОС на Windows временный `prisma/e2e-*.db` может остаться; это только изолированные тестовые данные. Схема миграций: `prisma/migrations/`. Для будущих изменений схемы используйте `npx prisma migrate dev --name descriptive_name`; существующие применённые миграции не редактировать.

## Запуск собранного интерфейса

```powershell
npm run build
$env:APP_ORIGIN="http://127.0.0.1:3001"
npm start
```

Адрес: http://127.0.0.1:3001. Сервер раздаёт и API, и `dist/`. Это локальный запуск: TLS и публичное развёртывание здесь не настроены. `APP_ORIGIN` должен совпадать с адресом страницы. Сервер по умолчанию слушает только loopback.

## Переменные окружения

| Переменная | Значение |
| --- | --- |
| `DATABASE_URL` | `file:./dev.db`; относительный путь считается от `prisma/`. Это постоянный файл, не localStorage. |
| `PORT` | API/Socket.IO, по умолчанию 3001. Dev-прокси Vite рассчитан на 3001. |
| `APP_ORIGIN` | Единственный разрешённый origin страницы, по умолчанию `http://127.0.0.1:5173`. |
| `NODE_ENV` | В production включает Secure-cookie; требуется HTTPS. |

Секретов по умолчанию нет. Session token создаётся криптографически случайным, в БД хранится только SHA-256-хеш. `.env` и БД исключены из Git. Пароли хешируются bcrypt с cost 12; принимаются 10–72 символа, не более 72 UTF-8 байт. Сессия живёт семь дней, HttpOnly, SameSite=Lax; выход отзывает сессию и отключает её сокеты. Cookie Secure включается в production. Изменяющие HTTP-запросы требуют точного Origin, socket handshake также проверяет Origin. CORS не использует wildcard.

## Реализовано

- Регистрация, вход, выход, текущий профиль; реальные независимые пользователи.
- Поиск пользователей по имени/email, создание личного диалога без дублирования пары.
- Список диалогов с последним сообщением и временем; фильтр по имени собеседника.
- История с устойчивым порядком по серверному ID и пагинацией; сохранение после перезапуска.
- Socket.IO: отправка → запись в БД → событие участникам и ack отправителю.
- Идемпотентность по `(senderId, clientMessageId)`; повтор после ошибки использует тот же UUID.
- После reconnect клиент дочитывает все сообщения после последнего известного ID, пакетами, включая длинный офлайн. Socket-события не считаются постоянным хранилищем.
- Онлайн-статус по соединениям с учётом нескольких вкладок; typing с ограничением частоты и автоматическим истечением.
- Проверка сессии и членства на чтении, отправке, join и typing. Третий пользователь не получает события диалога.
- Zod-валидация, лимит текста 4000 символов, rate limiting авторизации и socket-событий, Helmet, текстовый вывод сообщений без HTML.
- Загрузка, пустые состояния, сетевые ошибки, повтор отправки, сохранение позиции при чтении старой истории, адаптивный список/чат на телефоне.

Галочка означает **сохранение на сервере**, а не прочтение собеседником. Счётчики непрочитанного и read receipts не реализованы. Поиск по содержимому сообщений отсутствует — поле явно ищет диалоги по имени.

## Границы MVP и дальнейшие работы

`npm audit` после установки исправленных транзитивных зависимостей сообщает 0 уязвимостей. `package.json` закрепляет overrides для `deepmerge-ts` и `effect` внутри `@prisma/config`; совместимость проверяется генерацией клиента, миграциями и тестами. При обновлении Prisma пересмотрите необходимость overrides.

Это локальный многопользовательский MVP, без заявления о production-ready. Неактивные демонстрационные возможности исходника (стена, фиктивные звонки, вложения, ручной онлайн-статус, локальные демопрофили) не выданы за работающие серверные функции и не включены в интерфейс. Общая сетка и стилистика сохранены; правая панель показывает профиль и информацию о мессенджере. Редактирование профиля и аватары, группы, медиа, уведомления, восстановление пароля и подтверждение email остаются отдельными расширениями.

Выбран документированный SQLite-режим разработки, поскольку PostgreSQL и Docker отсутствовали в окружении. PostgreSQL-провайдер и миграции для него ещё не подготовлены: нельзя просто поменять URL. Следующий шаг для серверного развёртывания — PostgreSQL-схема/миграции и перенос данных, TLS/reverse proxy, резервные копии с проверкой восстановления, мониторинг, email verification/reset и нагрузочное тестирование. Presence/rate limits/typing сейчас в памяти одного процесса; для нескольких экземпляров понадобятся общий adapter/broker и распределённые лимиты.

Использованные технические ориентиры: [Socket.IO — восстановление после отключений](https://socket.io/docs/v4/tutorial/handling-disconnections), [Prisma CLI](https://docs.prisma.io/docs/orm/reference/prisma-cli-reference).
